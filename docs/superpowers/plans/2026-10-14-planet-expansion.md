# Planet Expansion Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Execute ONE user-approved task per turn, then stop for user testing. Do not automatically continue into the next task.

**Goal:** Розширити Crust-to-Crust узгодженими біомами, подіями, модулями, косметикою та режимами, зберігши основу гри й прогрес користувача.

**Architecture:** Нові вузькі компоненти підключаються до існуючих `RunDirector`, `LevelGenerator`, `Player`, `SaveData` і `AudioManager`. Координація небезпек передує великим подіям; статистика передує нагородам і режимам. Не вводити всі компоненти одночасно.

**Tech Stack:** Godot 4.7.2 Mono, C# / .NET 8; локальна генерація аудіо, imagegen за потреби; чинні smoke-сцени.

**Spec:** `docs/superpowers/specs/2026-10-14-planet-expansion-design.md`

## Global Constraints

- Одне завершене завдання, показ результату, зупинка; наступне лише після прямого «далі».
- Газ біля стін: приблизно 25% локальної ширини тунелю; одна шкала перегріву.
- Зберегти швидкість повернення, темряву, заряд, батарейки, покупки, рекорди й геймпад.
- Не використовувати платні сервіси без погодження; не змінювати особистий save у тестах.
- Зберегти музику меню з шумом і основну композицію гри.
- Окремі режими мають окремі результати й правила; примари прив'язані до версії маршруту.

## Review Focus

- Максимальна швидкість: попередження доступне до контакту, існує досяжний шлях.
- Пул: повторна поява не успадковує старий звук, стан, нагороду чи колізію.
- Пауза/смерть/перезапуск: таймери та сигнали не створюють пізніх небезпек.
- Старі збереження: нові поля мають безпечні значення, старі IDs залишаються чинними.
- Поєднання подій: один координатор не допускає суперечливих небезпек і перекритого охолодження.
